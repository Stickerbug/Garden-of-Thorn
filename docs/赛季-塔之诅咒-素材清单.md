### 1.1 皮肤分类（一般 / 特殊）

2026-11-11 起皮肤分两类，分类与绑定都写在 `card_skins.py` 的
`CARD_SKIN_CATALOG` 里（唯一来源），不再按 id 前缀判断：

| 分类 | layout | 成员 | 卡面元素 |
|---|---|---|---|
| 一般皮肤 `normal` | `default` | 区、叶框、金叶框、绷带、标靶、蠕虫、阴阳、阴阳玉 | 默认数据显示位置 |
| 特殊皮肤 `special` | `mana_on_star` | 塔之诅咒五款 | 按卡面自带徽记特殊绑定 |

- 常量：`SKIN_CATEGORY_{NORMAL,SPECIAL}`、`SKIN_LAYOUT_DEFAULT`、
  `SKIN_LAYOUT_MANA_ON_STAR`；`skin_layout(id)` / `skin_category(id)`
  对空值、未知 id 一律回落成一般皮肤（默认布局），不会误加特殊绑定。
- 下发：`card_skin_payload()` 与日常商店的每个 item 都带
  `category` / `layout`；客户端把它们缓存进 `window.__cardSkinCatalog`。
- 客户端：`cardSkinLayout(skinId)` 取布局，只有
  `layout === 'mana_on_star'` 才给卡片加 `card-mana-on-star` 类。
  目录接口失败时回落默认布局（等价一般皮肤），退化为普通卡面而不是画错。
- 加一款特殊皮肤 = 在 `CARD_SKIN_CATALOG` 里写 `layout`，再在 `style.css`
  里补一套该 layout 的规则；不需要改客户端判断。
- 数据库：`card_skin_catalog` 新增 `layout` 列（老库自动 `ALTER TABLE` 补，
  默认 `default`），种子按目录 upsert 回填。

### 1.2 卡面徽记与消耗数字

- 五款卡面自带两个徽记：左上角橙色六边形（能量位）、左中蓝色辉星
  （`fill: #3abee8`，`d="M343.1,285.1…"`，魔力位）。
- 装备这五款皮肤时，能量/魔力消耗**只显示数字**，圆形外框与底色都去掉，
  数字各自落在自己徽记的正中间，颜色沿用资源色（能量黄 `var(--elixir)`、
  魔力蓝 `var(--magic)`）：
  - `static/js/game.js`：`layout === 'mana_on_star'` 的皮肤给卡片加
    `card-mana-on-star` 类（见 §1.1）；
  - `static/css/style.css`：该类下两个消耗球 `border-color`/`background` 置空
    （只改颜色不删 border，宽度不变），并绝对定位到徽记中心。
- 坐标由卡面图换算（皮肤图按 `182.3%` 卡宽居中渲染，卡宽:卡高 = 63:88）：
  - 六边形中心 SVG(323.1, 198) → 卡宽 `10.8%`、卡高 `7.53%`
  - 辉星中心 SVG(259.6, 285.5) → 卡宽 `0.59%`、卡高 `17.61%`
- 魔力消耗因此从原来的右上角挪到辉星；辉星本身跨在卡框左边缘上，
  所以数字也有一半在卡框外（与星形一致）。两个球都脱离 flex 流后，
  卡名左右各补同等宽度，居中位置不变。
- 换卡面图若徽记位置变化，需同步改 CSS 的百分比与
  `tests/test_tower_curse_assets.py` 里的断言。
- 卡面的黄色内框内沿底边在 SVG `y=551.3`（卡高约 `48.2%`），底部中央另有一个
  金色小标签（`rect` x488 y535.2 宽157.9 高61.4，下沿 `y=596.6` ≈ 卡高 `53.4%`），
  左右红边各占约 `6.2%` / `7.3%` 卡宽。默认描述会压黄线、首字压进左边红边。
  这五款皮肤下给 `.card-effect` 额外补内距（都叠加在 `--card-effect-*` 变量上，
  保留卡片自身缩放）：上 `+8cqi`、左右各 `+4.5cqi`（合 7cqi），描述从金色小标签
  下方、红边右侧开始。
- 上内距为什么是 `+8cqi` 而不是刚好避开黄线：金色小标签比黄框内沿再往下探一截，
  只按黄线算不够。实测（300px 宽、卡高 419 的卡）：`+4cqi` 时字形上沿 52.3%，
  其实压在标签上；`+6cqi` 时 53.7%，只是刚好贴住标签下沿；`+8cqi` 时 55.2%，
  落在标签下方约 1.8% 卡高。若日后换的卡面没有这个下方标签，可回调到 `+4cqi`。
- 注意 `fitCardEffectText()` 在文字溢出时会等比缩小字号**并等比缩小内距**，
  所以长描述卡（缩到 0.6 时）这个下移量会跟着变浅；多数卡 `effectFitScale=1`，
  不受影响。
- 描述文字为纯白：卡面是纯色底，不需要皮肤墨色自适应的逐像素贴图，
  故 `.card-effect .skin-ink` 去掉 `background-image` 并 `!important` 压白
  （inline 的 `color: transparent` 也必须用 `!important` 盖过）。
  伤害数字等由 `colorizeCardText` 上色的片段仍保留原色。
- 魔力数字固定用 `var(--magic)`：皮肤墨色自适应会按辉星底色把数字改写成深一档
  的蓝（看着发黑），故 `.cost-m` 及其 `.skin-ink` 压掉贴图并 `!important` 上色；
  不加描边——字号只有 ~9cqi，描边会吃掉笔画。
- 卡名的英文翻译行（`.card-english-name`）在这五款卡面下隐藏；用
  `visibility: hidden` 保留占位——这一行的高度正好是卡面黄框绘图窗的上沿，
  抽掉会让卡图整体上移压到黄边。类型标签（如 `Thorn`）不属于翻译行，保留。
- 卡图（`.card-art`）对到卡面绘图窗口上，插画因此放大一倍：黄框内开口
  SVG `x=307.7~826.2`、`y=217.2~551.3` → 卡面左 `8.32%`、宽 `83.37%`、
  上 `9.72%`、高 `38.46%`（绝对定位，`border-radius: 0`，透明底）。
  原来卡图盒只有 `25cqi` 高（≈卡高 17.9%），`object-fit: contain` 的方图被
  高度卡住，看着比窗口小一大截；撑满窗口后图片高度变成原来的 2.15 倍。
  - 卡图脱离流后，`.card-art ~ .card-type-label-wrap` 补 `margin-top: 25.1cqi`
    （原卡图占的 25cqi + 0.1cqi 外边距），描述与类型标签位置不变；用相邻兄弟
    选择器是为了让「没有卡图」的卡不受影响。
- 类型标签（`.card-type-label`）挪进卡面底部中央的金色小标签里
  （对应 SVG `rect` 中心 `(50%, 49.88%)`，宽 `25.39%` 卡宽、高 `7.07%` 卡高）。
  - 用 `position: absolute` 钉到卡面坐标，**不用** `translateY` 平移：
    no-english 卡片里 `.card-art{margin-bottom:-1.15cqi}` +
    `.card-type-label-wrap{margin-top:-0.9cqi}` 会让标签在流内高约 2cqi，
    平移量就不准了；绝对定位让两种卡片都落在同一处。
  - `.card-type-label-wrap` 保留原占位高度 `9.67cqi`（= 6.5cqi 字号 × 行高 +
    上下 0.5cqi 内距），否则 `.card-effect` 整体上移、描述会压回金色小标签。
  - 字号 `6.2cqi`（标签高 ≈ 9.9cqi，字形约占标签高六成）；金色标签上改用深棕
    `#4a2b06`——类型色 `--thorn/--bloom/--root/--guard` 是亮色，压在
    `#eace2f` 的金色上几乎看不见。模板内联的类型色需 `!important` 才盖得住。
- 卡名在该卡面下为白字 + 深红描边（`#8f2a16`，八向 `em` 硬投影，不用
  `-webkit-text-stroke`——后者会内缩字形，小字号笔画会被啃细），字号取
  `--card-name-font-scale` 的 `90%`；并整体落在黄条内：黄条占卡高
  `3.03%~10.33%`，字身原本 `4.41%~11.29%`（底部垂到黄条外），
  `translateY(-1.6cqi)` 后落在 `3.3%~10.2%`。白字要 `!important`
  才压得过模板给的内联类型色。

## 5. 备注

- 玩家皮肤贴图统一到同一视觉大小（2026-11-11）：头像用
  `object-fit: contain` 铺满方框，所以显示大小完全由 SVG `viewBox` 里的留白
  决定。Illustrator 导出的新素材四周留了一圈空白（内容只占 42%~70% 画布），
  同一头像框里看着小一号。处理办法是把每个 `viewBox` 收紧到「内容包围盒 +
  2% 留白」，已铺满画布的（`faceless/ghost/brain-damage/corrupted/mark/nazar/
  right-angle`）保持不动。归一化后全部约为画布的 `98%`。
  - 改过的文件：`centipede-head`、`desert-centipede-head`、
    `evil-centipede-head`、`tower-curse-{ironclad,silent,defect,necrobinder,
    regent}`。
  - 贴图 URL 带 `?v=<PLAYER_SKIN_ART_REVISION>`（在 `static/js/player-skins.js`），
    换图后 bump 它即可让缓存失效；它不随整体静态版本每次部署变化。
  - `tests/test_player_skin_assets.py` 锁住了归一化结果，重新导出素材若又带回
    空白会直接失败——重新量一遍后更新该测试里的期望值。
- 原始 `.ai` 文件未入库，只入库了 SVG。
- 卡牌皮肤已按现有 `1133.86` 方形规格导入；玩家皮肤使用 `283.5` 画布；背景为 `1366×768`。
