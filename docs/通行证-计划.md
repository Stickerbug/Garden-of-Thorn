## 3. 经验（XP）系统

### 3.1 对局经验

```python
base = min(40, ceil(seconds / 10), turns * 5)      # turns = max(双方回合数)，见 D2
gain = floor(base * 1.5) if win else base          # 官方定义，向下取整
```

- `seconds`：本局时长（秒），取服务端记录的 `started_at → ended_at`，**不信客户端**。
- `turns`：**单方最大回合数** `max(turns_a, turns_b)`（D2）。
- 有效对局才发：见 §10 风控（时长 ≥ 90s、双方各 ≥ 3 回合、非 AI 对局）。
- 单局硬上限 60（`floor(40*1.5)`），作为断言写进测试。

### 3.2 爬塔经验

```python
score = compute_score(state, difficulty, load_count)[0]
gain  = min(1000, ceil(score / 5))
```

- 触发点：`story_engine.py:266-270` 结算分支（通关即可，失败不给）。
- 幂等键：`ref = run_id`，一局只发一次。
- 每日软上限：3 局（Q1 可调），超额仍记录但不计入 XP。

### 3.3 签到经验（替换荆露）

- 现：签到发 40/45/50/55/60/70/100 荆露（按连续天数）。
- 改：同一算式结果**作为等量 XP 发放**，不再发荆露。
- 实现：`claim_user_daily_checkin` 里 `reward = scale_dew_gain_conn(...)` 之后不写 `thorn_dew_free`，而是 `grant_xp(uid, reward, source='checkin', ref=checkin_date)`；`user_daily_checkins.reward` 列语义改为"本次获得的 XP"，注释同步。
- **经济影响**：签到是稳定的每日荆露水龙头（40–100/天，7 天一轮 420）。取消后荆露收入约降 25%–35%（视对局量）。已确认接受（D1）。

### 3.4 升级与泡泡推进

```python
level = xp // 100               # 不封顶：100 级后继续升，每级发循环格奖励（D4）
bubble_index = min(level, 100)  # 泡泡棋子只在 1..100 格内移动，超出后停在终点并显示「+N」
```

- 泡泡是 UI 状态，不落库；落库的只有 `xp` 与 `claims`。
- 动画：升级时泡泡沿轨道平滑移动到 `level` 格（CSS `transform: translateX()` + `transition: .5s cubic-bezier(.34,1.56,.64,1)`），到达时轻微弹跳。

### 3.5 赛季

- 通行证必须有赛季边界，否则 100 级会被"一次完成、永久满级"。
- 新表 `pass_seasons` 配 `starts_at / ends_at`；第一期与「塔之诅咒」赛季对齐，**2026-11-11 00:00 → 2026-11-30 23:59**（Q5，原定 8 周，2026-11-12 按用户要求缩短）。
- 赛季切换：`user_pass` 按 `(user_id, season_id)` 分行，旧赛季数据只读保留（可做历史查看）。
- XP 不跨赛季结转。

## 4. 双轨 100 格

### 4.1 结构

- **荆棘之路（free）**：所有人可领，每格都有奖励。
- **黄金之路（golden）**：花 250 金露解锁，解锁后**已到达的格子可补领**（不回溯发经验，只回溯发奖励）。
- 两轨同一等级：`level` 决定可领取到第几格。

### 4.2 逐格奖励表（定稿）

**个位格（1–9）**——每 10 级重复一次，共命中 10 次（1–9、11–19、…、91–99）：

| 个位 | 荆棘之路（普通） | 黄金之路（进阶） |
|------|------------------|------------------|
| X1 | 200 荆露 | 保分卡 ×1 |
| X2 | 保分卡 ×1 | 100 荆露 |
| X3 | 200 荆露 | 双倍卡 ×1 |
| X4 | 休闲花园门票 ×1 | 100 荆露 |
| X5 | 5 金露 | 休闲花园门票 ×1 |
| X6 | 双倍卡 ×1 | 100 荆露 |
| X7 | 200 荆露 | 双倍卡 ×1 |
| X8 | 休闲花园门票 ×1 | 100 荆露 |
| X9 | 200 荆露 | 保分卡 ×1 |

**整十格（10–100）**——每 10 级一个里程碑，不重复：

| 格 | 荆棘之路（普通） | 黄金之路（进阶） |
|----|------------------|------------------|
| 10 | 一个称号 | 一个卡背 |
| 20 | 1000 荆露 | 一个称号 |
| 30 | 一个卡背 | 一个皮肤 |
| 40 | 25 金露 | 500 荆露 |
| 50 | 一个皮肤 | 一个卡背 |
| 60 | 一个背景 | 一个皮肤 |
| 70 | 1000 荆露 | 一个卡背 |
| 80 | 一个皮肤 | 一个背景 |
| 90 | 25 金露 | 500 荆露 |
| 100 | 一个卡背 | 一个皮肤 |

**100 级之后（101+）**——可无限累计的循环格：

| 格 | 荆棘之路（普通） | 黄金之路（进阶） |
|----|------------------|------------------|
| 101+ | 100 荆露 / 格 | 50 荆露 / 格 |

实现即纯查表，不需要生成器：

```python
PATTERN_FREE   = {1: ('thorn_dew', 200), 2: ('shield', 1), 3: ('thorn_dew', 200),
                  4: ('leisure_ticket', 1), 5: ('golden_dew', 5), 6: ('double', 1),
                  7: ('thorn_dew', 200), 8: ('leisure_ticket', 1), 9: ('thorn_dew', 200)}
PATTERN_GOLDEN = {1: ('shield', 1), 2: ('thorn_dew', 100), 3: ('double', 1),
                  4: ('thorn_dew', 100), 5: ('leisure_ticket', 1), 6: ('thorn_dew', 100),
                  7: ('double', 1), 8: ('thorn_dew', 100), 9: ('shield', 1)}
MILESTONE = {10: (...), 20: (...), ...}      # 10 条，按上表逐条写死
OVERFLOW   = {'free': ('thorn_dew', 100), 'golden': ('thorn_dew', 50)}

def reward_for(level: int, track: str):
    if level > 100: return OVERFLOW[track]
    if level % 10 == 0: return MILESTONE[level][track]
    return (PATTERN_FREE if track == 'free' else PATTERN_GOLDEN)[level % 10]
```

### 4.3 全表合计

| 项 | 荆棘之路（免费） | 黄金之路（250 金露） |
|----|------------------|----------------------|
| 荆露 | **10,000** | **5,000** |
| 金露 | **100** | 0 |
| 保分卡 | 10 | 20 |
| 双倍卡 | 10 | 20 |
| 休闲花园门票 | 20 | 10 |
| 称号 | 1 | 1 |
| 卡背 | 2 | 3 |
| 皮肤 | 2 | 3 |
| 背景 | 1 | 1 |
| 100+ 循环 | 100 荆露 / 级 | 50 荆露 / 级 |

两条结论：

1. **普通轨的经济量大于进阶轨**（荆露 10,000 vs 5,000，还多 100 金露）。进阶轨的价值全在外观（皮肤 3 / 卡背 3 / 背景 1 / 称号 1）与道具（保分卡 20 / 双倍卡 20）。若想让进阶轨"看起来更值"，把进阶轨里程碑的 500 荆露提到 1000，或给 L100 加专属称号。
2. **普通轨的 100 金露 = 票价的 40%**，等于免费玩家攒 100 金露就能半价买黄金之路，属于设计选择，确认保留即可。
3. 休闲花园门票有 `TICKET_CAP = 5`（`leisure_ticket.py:20`），20 张门票会溢出——**溢出怎么处理**见 Q2。

### 4.4 美术与条目依赖（上线前必须备齐）

| 类 | 数量 | 现状 |
|----|------|------|
| 皮肤 | 5（普 2 + 金 3） | 需新建 `card_skins.CARD_SKIN_CATALOG` 条目 + front/back SVG |
| 卡背 | 5（普 2 + 金 3） | 卡背是 card skin 的后背图（`card_skins.py` 头部注释：装备皮肤后所有手牌卡背换成该皮肤的卡背图；默认卡背「初始」免费）。「只发卡背」= 新增一条 front 复用默认、仅换 back 的皮肤条目 —— 需你确认是否接受这种"半套皮肤" |

## 5. 黄金之路四项增益

| 增益 | 实现点 | 注意 |
|------|--------|------|
| 荆露获取 ×1.5 | `db.scale_dew_gain_conn(conn, amount)` 增加可选 `user_id` 参数（`scale_dew_gain_conn(conn, amount, user_id=None)`），有 user_id 且其为黄金持有者时再 ×1.5；5 个调用点逐一补 `user_id` | 现函数签名只有 `(conn, amount)`，必须改签名，否则拿不到用户；改动面 5 处，全部在 `db.py` + `pvp_economy.py` |
| 经验获取 ×1.5 | `grant_xp()` 内 `amount = floor(amount * 1.5)`，并写日志 `multiplier` 列 | 只作用于"获得"，不作用于"补发/补偿" |
| 天梯特殊修正 +2 | `db.py:15605` 与 `db.py:17361` 两处 `special_total` 求和时加 `pass_rank_special_bonus(conn, user_id)` | **不写 `users.rank_special`**（写字段会在赛季结束后残留；读时叠加才随赛季消失）。注意 `match_gain` clamp 上限 20、`match_loss` 下限 1，高段位时 +2 可能被 clamp 吃掉——这是既有行为，接受 |
| 签到额外发卡 | `claim_user_daily_checkin` 里黄金持有者 `rank_shield_cards += 1`、`rank_double_cards += 1` | 与"签到发 XP"同一事务提交 |

## 6. 数据模型

```sql
CREATE TABLE IF NOT EXISTS pass_seasons (
    id            TEXT PRIMARY KEY,
    title         TEXT NOT NULL,
    starts_at     TEXT NOT NULL,
    ends_at       TEXT NOT NULL,
    golden_price  INTEGER NOT NULL DEFAULT 250,
    max_level     INTEGER NOT NULL DEFAULT 100,
    xp_per_level  INTEGER NOT NULL DEFAULT 100,
    created_at    TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS user_pass (
    user_id            INTEGER NOT NULL,
    season_id          TEXT NOT NULL,
    xp                 INTEGER NOT NULL DEFAULT 0,
    golden_owned       INTEGER NOT NULL DEFAULT 0,
    golden_purchased_at TEXT,
    updated_at         TEXT NOT NULL,
    PRIMARY KEY (user_id, season_id),
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS user_pass_xp_log (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id    INTEGER NOT NULL,
    season_id  TEXT NOT NULL,
    source     TEXT NOT NULL,      -- match | story | checkin
    ref        TEXT NOT NULL,      -- 对局 id / run_id / checkin_date
    base       INTEGER NOT NULL,   -- 未乘增益的原始值
    multiplier REAL NOT NULL DEFAULT 1.0,
    amount     INTEGER NOT NULL,   -- 实发
    created_at TEXT NOT NULL,
    UNIQUE (user_id, season_id, source, ref)   -- 幂等的关键
);

CREATE TABLE IF NOT EXISTS user_pass_claims (
    user_id    INTEGER NOT NULL,
    season_id  TEXT NOT NULL,
    level      INTEGER NOT NULL,
    track      TEXT NOT NULL,      -- free | golden
    claimed_at TEXT NOT NULL,
    PRIMARY KEY (user_id, season_id, level, track)
);
```

- 迁移：全部 `CREATE TABLE IF NOT EXISTS`，无 ALTER，老库零风险；`_ensure_pass_schema(conn)` 在 `init_db` 里调用。
- 幂等：`user_pass_xp_log` 的 UNIQUE 用 `INSERT OR IGNORE`，插入成功才 `UPDATE user_pass SET xp = xp + ?`，断线重连/重放结算不会双发。
- `user_pass.updated_at` 供后台风控查询"异常高 XP 用户"。

## 9. 结算时序

```
对局结束
  ├─ 既有：段位结算 / 荆露结算（pvp_economy）
  ├─ 新增：xp = min(40, ceil(sec/10), turns*5) [×1.5 若胜]
  └─ grant_xp(conn, uid, xp, 'match', match_id)      # UNIQUE 天然幂等

爬塔结算（story_engine.py:266-270）
  ├─ 既有：compute_score → 记录
  └─ 新增：grant_xp(conn, uid, min(1000, ceil(score/5)), 'story', run_id)

签到（db.claim_user_daily_checkin）
  ├─ 既有：连续天数、修饰符、休闲券
  ├─ 改：荆露 → grant_xp(..., 'checkin', checkin_date)
  └─ 新增：黄金持有者 +保分卡 1 +双倍卡 1
```

XP 全部服务端计算并写日志，客户端只读 `/api/pass/state` 的结果；前端不做任何 XP 数学。

## 10. 反作弊与风控

| 风险 | 对策 |
|------|------|

## 13. 数值预估（100 级 = 10000 XP）

S1 实际窗口：2026-11-11 00:00 → 2026-11-30 23:59（20 个自然日，19 天 23 小时 59 分）。假设：日均 5 局、平均 30 XP/局（胜率 50%）+ 签到平均 55 XP。

| 玩家类型 | 日均 XP | 20 天总量 | 可达等级 |
|----------|---------|-----------|----------|
| 只签到 | 55 | 1,100 | 11 |
| 轻度（2 局/天） | 115 | 2,300 | 23 |
| 中度（5 局/天） | 205 | 4,100 | 41 |
| 中度 + 黄金之路 | 307 | 6,140 | 61 |
| 重度（10 局/天 + 2 局爬塔） | 620 | 12,400 | 100（第 17 天满级） |

结论：20 天内满级需要日均 500 XP，基本只有「重度对局 + 每周前 3 次爬塔 ×3」才够；中度玩家本季大致停在 40–60 级，黄金之路把同样投入抬到 60 级上下。溢出的循环格（100/50 荆露）只有重度玩家会碰到。若希望更多人满级，把 `XP_PER_LEVEL` 降到 80 或把爬塔每周 ×3 提高到 5 次。
