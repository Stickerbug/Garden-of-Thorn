# 部署与更新流程（2026-11-15 起）

## 1. 硬性规则

**任何一次上线都必须先广播，再等满 5 分钟才切换服务。**

广播文案固定为：

> 五分钟后更新，请大家尽快结束对局

同一时间，所有在线页面的**最顶端**会出现一条红色公告条（文案 + `剩余 M:SS` 倒计时），刷新页面也还在，到期自动收起。

5 分钟不是「大约」：广播成功后计时，整 300 秒时才允许 `systemctl stop/start gtn-release`。
演练时可以临时改 `GTN_NOTICE_WAIT_SECONDS`，正式上线一律用默认值。

## 2. 一条命令完成

在服务器上（root）：

```bash
bash /tmp/gtn_update.sh /tmp/gtn-deploy.tgz <git-sha>
```

脚本顺序是固定的：

1. 把发布包解到 `/opt/gtn-stage`（`--strip-components=1`），先 `py_compile` 校验，**此时线上仍在跑旧版**；
2. 调 `gtn_broadcast.py` 发全服广播，并在页面最顶端挂出带倒计时的公告（默认比等待多 2 分钟，覆盖重启窗口）；
3. `sleep 300`；
4. 停服 → 迁移 `venv` → 目录对调（旧版留在 `/opt/gtn-release.old`）；
5. 只改 `/etc/gtn/release.env` 里的 `GTN_VERSION` / `GTN_GIT_SHA` / `GTN_STATIC_VERSION` 三行；
6. 启动并轮询 `/api/version` 直到出现新 SHA，打印 `VERSION_OK`。

手动分步时顺序不变：**先广播，再 sleep 300，最后才切换**。

## 3. 广播是怎么发出去的

`scripts/gtn_broadcast.py`（可单跑）：

```bash
/opt/gtn-release/venv/bin/python scripts/gtn_broadcast.py \
  --seconds 420 "五分钟后更新，请大家尽快结束对局"
```

- 从运行中进程的环境变量（`/proc/<pid>/environ`，或当前 shell 的 `SECRET_KEY`）取 `SECRET_KEY`；
- 用它签一枚有效期数分钟的「管理控制台」会话 cookie；
- 调既有的 `POST /api/adminconsole/command`，执行管理台命令 `maintenance notice <秒数> <内容>`；
- 服务端一边把文案发进聊天广播（`send_system_broadcast()`），一边记住公告状态，并通过
  `socketio.emit('maintenance_banner')` 推给在线页面；没连 socket 的页面每 15 秒拉一次
  `GET /api/maintenance/notice` 对齐；
- 旧版服务端没有 `maintenance` 命令时脚本自动回退到 `lobby broadcast <内容>`（只有聊天广播，没有顶部公告）。

因此**没有新增任何公网接口**，也不需要把管理台密码写进脚本；脚本不打印 `SECRET_KEY`。

边界：

- 服务若用进程内临时密钥（启动日志出现 `SECRET_KEY is not configured`），代签的 cookie 无效，脚本会报错退出；
- 需要 root（读 `/proc/<pid>/environ`）与 `systemctl`。

## 4. 验证

```bash
# 广播确实执行了
journalctl -u gtn-release --since '-10 min' | grep -i broadcast

# 顶部公告处于生效状态
curl -s http://127.0.0.1:5000/api/maintenance/notice

# 新版本已生效
curl -s http://127.0.0.1:5000/api/version

# 服务与错误日志
systemctl is-active gtn-release
journalctl -u gtn-release -p err --since '-10 min'
```

浏览器侧：任一在线页面会收到「[系统]五分钟后更新，请大家尽快结束对局」提示，并且页面最顶端出现同文案的公告条与倒计时。

## 5. 首次使用（脚本还没进线上目录）

`gtn_update.sh` 会在三个位置找广播工具：当前 release 的 `scripts/`、`/usr/local/sbin/gtn-broadcast`、脚本自身同目录。
第一次上线时线上还没有这个文件，把两个脚本一起传到 `/tmp` 再执行即可：

```bash
scp scripts/gtn_update.sh scripts/gtn_broadcast.py root@<host>:/tmp/
ssh root@<host> 'bash /tmp/gtn_update.sh /tmp/gtn-deploy.tgz <sha>'
```
